# 全国知识产权案例库扩容与质量分析日志（2026-08-28）

## 目标与结果

本轮目标是把既有 1,220 条全国知识产权案例索引扩大 5 倍。最终得到 6,100 条，新增 4,880 条，达到 `1,220 × 5 = 6,100` 的目标。

## 裁判文书网登录与检索入口

用户提供的中国裁判文书网会话已确认处于登录状态，公开检索入口可访问。本轮没有绕过验证码、反爬、登录或付费限制；自动化页面在批量详情抓取时出现不稳定，因此没有把“已登录”误写成“已逐案人工核验”。最终新增样本采用明确声明来源为裁判文书网的公开研究语料，并把官方检索入口和数据集分片/行号写入每条记录。

## 数据来源与选择

1. **C3RD / MileCut**：数据说明称由中国裁判文书网公开民事文书构建。解压后按 `CaseId` 去重，知识产权关键词命中样本 1,414 条，最终选入 1,097 条。
2. **TheFinAI corpus-shard-20**：公开法院裁判语料分片（页面标注 Apache-2.0）。本轮缓存 34 个 parquet 分片，关键词筛选 4,753 条，最终选入 3,783 条。
3. **既有索引**：继续保留人民法院案例库、最高人民法院年度典型案例、Figshare CC BY 4.0 惩罚性赔偿样本、北大法宝索引、裁判文书网列表摘要及福建高院公开记录。
4. **候选但未入库**：AppealCase（CC BY-NC 4.0）和 ClaimGen-CN（CC BY-NC-SA 4.0）已完成公开下载与筛选登记；由于前两类来源已达到 6,100 条目标，未把候选或非完整裁判文书片段混入最终库。

## 处理流程

1. 从 Git 历史恢复扩容前 1,220 条基线，避免把中间生成文件再次当作基线。
2. 对 C3RD、TheFinAI 数据逐条转换为统一字段：标题、案号、法院、案由、程序、日期、事实/说理摘要、来源入口、来源层级、引用定位和核验状态。
3. 采用标题+案号（有案号）或标题+正文哈希（无案号）去重，并在合并后再次按完整正文 SHA-256 去重。
4. 对手机号、18 位身份证号和 16—19 位银行卡号执行正则脱敏；公开机构统一社会信用代码等非个人字段不作过度清洗，但正式发布前仍建议人工抽查。
5. 通过 `scripts/ingest_cases.py` 导入 SQLite，移除三元组 FTS 以控制发布体积；`scripts/search_cases.py` 在没有 `cases_fts` 时使用结构化字段和可解释关键词评分。
6. 运行结构校验、重复检查、敏感信息正则检查、Python 编译检查和检索冒烟测试。

## 质量结果与解释

- `case_id` 唯一，完整正文哈希唯一；少量重复案号可能是不同程序、不同文书版本或机器抽取的案号误差，校验脚本会列为警告而不是自动删除。
- 新增 4,880 条均标记为“机器提取/待二次核验”，公开研究语料的 `source_url` 统一指向裁判文书网公开入口，具体分片与行号保存在 `citations`。
- `effective_judgment` 是数据结构中的来源类型名称，不代表本项目已人工核实每一条的生效状态；新增记录的 `effective_status` 明确写为待核实。
- 领域统计使用机器关键词和主标签，交叉案件会在多个领域的展示口径中出现，不能把各领域数量相加当作总数。

## 局限与下一步

- 研究语料、列表摘要和官方典型案例名单不能替代逐案打开裁判文书原文；正式法律意见必须重新核对案号、程序、权利基础、证据、法律版本、主文、赔偿金额和生效状态。
- 公开裁判数据具有选择偏差，检索命中数和本库比例不能表示真实胜诉率或法院总体趋势。
- 若要继续提升“可引用性”，下一阶段应对高相关候选逐案回到裁判文书网、人民法院案例库或北大法宝页面人工复核，并给记录增加原文段落定位和复核人/复核日期。
- 第三方数据集按其发布页许可和访问条款使用；发布包不包含 C3RD、ClaimGen-CN 等原始大文件，仅提供结构化索引和来源说明。
