# 案例库扩容分析日志（2026-08-24）

## 1. 本轮目标与结论

本轮目标是把全国知识产权案例库从 610 条扩展到 1,220 条，同时提高去重质量、来源透明度和本地检索可用性。

最终结果：

| 指标 | 结果 |
| --- | ---: |
| 扩容前记录 | 610 |
| 清理旧库跨来源重复 | 23 |
| 扩容后保留旧记录 | 587 |
| 新增候选记录 | 795 |
| 候选阶段去重 | 89 |
| 去重后可用候选 | 706 |
| 实际选入新记录 | 633 |
| 最终记录 | 1,220 |
| 净增加 | 610 |
| 已知案号重复组 | 0 |

计算关系：`587 + 633 = 1,220`；相对于原始 610 条，净增长 `1,220 - 610 = 610`，扩容比例为 2.0。

完整机器审计见 [`data/national-ip-corpus/expansion-audit.json`](../data/national-ip-corpus/expansion-audit.json)。

## 3. 处理流程

1. 读取原 610 条结构化记录，按来源等级、案号、标题和正文摘要哈希识别跨来源重复。
2. 对同案多来源记录优先保留来源等级更高、可回溯性更强的版本。
3. 从 Figshare PDF 识别 245 个判决起始页，提取案号、标题、案由、程序、地区、裁判结果和页码定位。
4. 从最高人民法院年度页面提取 550 个典型案例索引。
5. 候选记录与保留旧库再次按案号、标题和摘要哈希去重。
6. 按目标总量选入 633 条，生成 JSON、SQLite 数据库、FTS5 全文索引、来源登记和审计文件。
7. 对结构字段、来源等级、URL、日期格式、摘要哈希和疑似敏感信息执行自动校验。

扩容脚本：[`scripts/expand_ip_corpus.py`](../scripts/expand_ip_corpus.py)。

## 6. 已知限制

- 这是法律研究索引，不是完整裁判文书镜像，也不是胜诉率数据库。
- `1900-01-01` 是“来源未提供准确裁判日期”的技术占位值，使用日期筛选时应排除或回到原文核验。
- 同一争议可能存在一审、二审、再审等多个不同案号；案号不同的程序文书不会仅因当事人相同而自动合并。
- 典型案例和人民法院案例库案例具有更高参考价值，但不等同于普遍拘束力。
- 机器提取的裁判结果、案由与程序必须在正式法律意见中回到原文复核。
- 公开裁判数据存在选择偏差，不能把样本中的支持比例直接表述为真实胜诉率。

## 7. 下一轮建议

1. 对高频检索领域建立人工复核优先队列，先补全裁判主文、金额、法律版本和证据要点。
2. 将 `1900-01-01` 改造为可空日期字段，避免技术占位值影响年份筛选。
3. 增加“同案不同审级”关系表，把一审、二审、再审文书串联为案件链。
4. 为商标合法来源、商业秘密保密措施、专利权利要求解释等高频争点建立专门标签。
5. 增加检索评测集，持续检测召回率、排序质量和来源等级偏差。

## 8. 合规说明

本项目不绕过验证码、登录验证、反爬措施或付费墙。付费数据库仅保存用户权限内可见的索引信息；公开判决数据保留来源、许可或官方页面。客户材料、未公开证据及个人敏感信息不得写入公共案例库。
