# 知识产权类案检索优化日志（2026-08-31）

## 本轮目标

在不改变现有 6,100 条案例索引的前提下，降低检索误排序，提升检索结果的可解释性，并建立可以重复运行的质量审计与回测流程。

## 发现的问题与处理

| 问题 | 优化方式 | 验证结果 |
| --- | --- | --- |
| 用户输入常常没有空格，例如“商标许可解除” | 增加轻量中文法律词切分，并保留原始查询 | 固定回测中的商标问题通过 |
| 同一法律概念存在多种表达 | 增加许可、终止、混淆可能性、软件、源代码、域名等同义词扩展 | 软件著作权与域名问题均命中预期案例 |
| 刑事、行政、执行文书可能干扰民事类案检索 | 增加文书类型推断；默认 `civil`，可用 `--matter all` 跨程序检索 | 3 组回测结果均未混入错误程序类型 |
| 机器结构化字段可能把正文段落误当标题、法院或案号 | 对疑似污染字段降权，并返回 `matched_fields`、`matched_terms` | 结果可解释性提升，避免单一污染字段主导排名 |
| 仅有人工抽查，难以持续发现数据问题 | 新增只读 `audit_case_fields.py` 字段质量审计 | 生成机器可读 `quality-audit.json` |
| 修改检索器后容易出现回归 | 新增三组固定夹具和 `run_ip_backtest.py` | 2026-08-31：3/3 通过 |

## 当前审计快照

审计不会删除记录，只标记需要回到原始来源复核的风险：

- 记录总数：6,100
- 标题疑似污染：497
- 法院字段疑似污染：710
- 案号占位或未识别：1,119（其中占位 1,118）
- 日期疑似占位：1,729
- 裁判文书网通用入口链接：4,880
- PII 正则命中：0
- 文书类型推断：民事 5,235、行政 318、执行 388、刑事 159

上述标记主要来自公开研究语料的机器结构化索引，并不等同于裁判文书原文存在错误。正式法律意见仍须核验原文、案号、裁判日期、法院、事实和主文。

## 可重复命令

```powershell
# 字段质量审计（只读）
python scripts/audit_case_fields.py --db data/national-ip-corpus/cases.db --out data/national-ip-corpus/quality-audit.json

# 固定回测
python scripts/run_ip_backtest.py --db data/national-ip-corpus/cases.db --out data/national-ip-corpus/backtest-results.json

# 全量结构校验
python scripts/validate_corpus.py --db data/national-ip-corpus/cases.db
```

## 下一轮建议

1. 对 1,119 条案号风险记录建立人工复核队列，并补录可直接打开的原始文书链接。
2. 在关键词检索之外增加 BM25 或向量召回，再用法律要素重排，降低同义表达遗漏。
3. 为每个案例增加“争议焦点—裁判规则—证据要求—赔偿结果”字段，并保留段落级引用。
4. 增加按法律版本、裁判年份和审级的时间轴，避免把旧规则直接套用到新案件。
